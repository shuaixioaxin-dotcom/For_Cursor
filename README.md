# Modbus RTU IMU测试工具（优化版）

## 问题分析与解决方案

### 原始问题
1. **严重丢包问题**
2. **偶发16ms延迟**（正常应为1ms左右）

### 根本原因

#### 16ms延迟问题
原代码使用 `time.sleep(0.0001)` (100μs) 进行轮询，在等待响应期间可能累积延迟：
- 100μs × 160次循环 = 16ms
- Windows系统的sleep精度问题会加剧延迟
- 轮询机制在高频场景下效率低下

#### 丢包问题
1. 轮询机制导致响应时间不够实时
2. 默认超时100ms过长，掩盖了问题
3. 发送后等待1ms可能不必要地降低了吞吐量

### 优化方案

#### 1. **移除轮询机制（关键优化）**
```python
# 原代码：轮询机制
while (time.perf_counter() - start_time) < timeout_sec:
    available = ser.in_waiting
    if available > 0:
        chunk = ser.read(available)
        buffer.extend(chunk)
    else:
        time.sleep(0.0001)  # ❌ 累积延迟的根源

# 优化后：阻塞式读取
ser = serial.Serial(..., timeout=args.timeout / 1000.0)
response = ser.read(RESPONSE_LEN)  # ✅ 使用串口自带超时
```

**优势：**
- 避免了 `time.sleep()` 的累积延迟
- 利用底层驱动的高效实现
- 响应时间更加稳定

#### 2. **优化默认参数**
```python
# 原代码
--timeout 100    # 100ms超时过长
--tx-wait 1      # 1ms等待可能过长

# 优化后
--timeout 10     # 10ms更合理
--tx-wait 0.2    # 0.2ms足够（RS485转向时间约0.1-0.2ms）
```

#### 3. **简化代码结构**
- 移除复杂的 `read_modbus_response()` 函数
- 简化错误处理逻辑
- 减少代码行数约20%

## 使用方法

### 基本用法

```bash
# 单个从站，最高频率
python modbus_rtu_test.py -p COM66 -i 1

# 多个从站（逗号分隔）
python modbus_rtu_test.py -p COM66 -i 1,2,3

# 多个从站（范围表示）
python modbus_rtu_test.py -p COM66 -i 1-5

# 指定读取频率
python modbus_rtu_test.py -p COM66 -i 1 -f 100

# 读取指定次数
python modbus_rtu_test.py -p COM66 -i 1 -c 1000

# 显示详细错误信息
python modbus_rtu_test.py -p COM66 -i 1 -v
```

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-p, --port` | 串口端口 | COM66 |
| `-b, --baudrate` | 波特率 | 921600 |
| `-i, --ids` | 从站ID列表 | 1 |
| `-f, --freq` | 读取频率Hz（0=最高） | 0 |
| `-c, --count` | 循环次数（0=无限） | 0 |
| `-d, --delay` | 从站间延时ms | 0 |
| `-t, --timeout` | 响应超时ms | 10 |
| `-w, --tx-wait` | 发送后等待ms | 0.2 |
| `-v, --verbose` | 显示详细错误 | False |

### 参数调优建议

#### 超时时间（`-t`）
- **921600波特率**：10-20ms
- **115200波特率**：20-50ms
- 公式：`超时 > (49字节 × 10位/字节 / 波特率) × 3`

#### 发送后等待（`-w`）
- **标准RS485**：0.2-0.5ms（芯片转向时间）
- **快速RS485**：0.1-0.2ms
- **USB转串口**：可能需要1-2ms

#### 从站间延时（`-d`）
- **总线负载低**：0ms
- **总线负载高**：1-5ms
- **多从站竞争**：根据实际情况调整

## 故障排查

### 仍有丢包
1. 检查RS485硬件连接（终端电阻、屏蔽）
2. 降低波特率测试（如改为115200）
3. 增加发送后等待时间 `-w 1`
4. 增加响应超时 `-t 20`
5. 使用 `-v` 查看详细错误信息

### 延迟仍然过高
1. 检查是否有其他程序占用串口
2. 尝试不同的USB端口
3. 更新USB转串口驱动
4. 检查系统负载（CPU占用）

### CRC校验失败
1. 检查波特率是否匹配
2. 检查RS485极性是否正确（A+/B-）
3. 减少线缆长度或改善屏蔽

## 技术细节

### Modbus RTU帧格式
```
请求帧（8字节）：
[从站ID] [功能码0x03] [起始地址H] [起始地址L] [寄存器数H] [寄存器数L] [CRC_L] [CRC_H]
[01]      [03]         [00]          [34]          [00]          [03]          [CRC]  [CRC]

响应帧（11字节）：
[从站ID] [功能码0x03] [字节数0x06] [AccX_H] [AccX_L] [AccY_H] [AccY_L] [AccZ_H] [AccZ_L] [CRC_L] [CRC_H]
[01]      [03]         [06]         [数据6字节..........................................] [CRC]  [CRC]
```

### 数据解析
```
加速度（6字节，寄存器0x34-0x36）：
- 地址0x34: AccX（16位无符号整数）
- 地址0x35: AccY（16位无符号整数）
- 地址0x36: AccZ（16位无符号整数）
- 转换公式：有符号值 × 0.0048828 = m/s²
- 有符号转换：值 >= 32768 时，实际值 = 值 - 65536
```
