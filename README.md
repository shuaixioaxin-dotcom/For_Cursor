# IMU数据采集频率优化项目

本项目提供了三个版本的代码，帮助将ESP32通过Modbus RTU读取IMU数据的频率优化到200Hz及以上。

## 📁 文件说明

### 代码文件

1. **原始代码**（用户提供）
   - 预期频率: 50-80Hz
   - 特点: 保守的超时和延迟设置，高稳定性

2. **`imu_optimized.ino`** ⭐ 推荐首选
   - 预期频率: 150-200Hz
   - 优化内容: 激进的时序参数调整
   - 适用场景: 稳定的RS485总线环境
   - 失败率: 预期 <5%

3. **`imu_ultra_optimized.ino`** 🚀 极限性能
   - 预期频率: 200-280Hz
   - 优化内容: 极限时序 + 减少寄存器 + 降低输出频率
   - 适用场景: 追求极限性能，硬件质量好
   - 失败率: 预期 5-10%

### 文档文件

- **`OPTIMIZATION_GUIDE.md`**: 详细的优化指南和性能分析
- **`README.md`**: 本文件，项目概览

## 🔧 关键优化参数对比

| 参数 | 原始值 | 优化版 | 极限版 | 说明 |
|-----|-------|-------|-------|------|
| RESPONSE_TIMEOUT_MS | 30ms | 8ms | 6ms | 响应超时 |
| BUS_SILENCE_US | 500us | 150us | 100us | 总线静默时间 |
| TX_ENABLE_DELAY_US | 30us | 10us | 5us | 发送使能延迟 |
| TX_DISABLE_DELAY_US | 60us | 20us | 10us | 发送禁用延迟 |
| MODBUS_REG_COUNT | 22 | 22 | 11 | 读取寄存器数 |
| OUTPUT_DIVIDER | 1 | 1 | 2 | 输出频率除数 |

## 📊 性能对比

### 理论分析

在921600波特率下：
- **通信时间** (22寄存器): ~1.2ms
- **通信时间** (11寄存器): ~0.7ms
- **目标周期** (200Hz): 5ms
- **每IMU预算** (2个设备): 2.5ms

### 预期性能表

| 版本 | 周期时间 | 理论频率 | 实际频率* | 稳定性 |
|-----|---------|---------|----------|--------|
| 原始 | ~15ms | 67Hz | 50-80Hz | ⭐⭐⭐⭐⭐ |
| 优化 | ~6ms | 167Hz | 150-200Hz | ⭐⭐⭐⭐ |
| 极限 | ~3ms | 333Hz | 200-280Hz | ⭐⭐⭐ |

*实际频率取决于硬件质量、总线长度、电磁干扰等因素

## ⚙️ 微调建议

### 如果频率不足200Hz

1. **减少输出频率**（极限版已实现）
```cpp
static const uint8_t OUTPUT_DIVIDER = 4;  // 每4个周期输出一次
```

2. **进一步降低超时**
```cpp
static const uint16_t RESPONSE_TIMEOUT_MS = 5;
```

3. **减少寄存器数量**（如果只需要部分数据）
```cpp
static const uint16_t MODBUS_REG_COUNT = 0x0007;  // 只读7个寄存器
```

### 如果失败率过高（>10%）

1. **增加超时时间**
```cpp
static const uint16_t RESPONSE_TIMEOUT_MS = 10;
```

2. **增加总线静默时间**
```cpp
static const uint32_t BUS_SILENCE_US = 250;
```

3. **检查硬件**
   - RS485总线长度（建议<50米）
   - 终端电阻（120欧姆）
   - 屏蔽和接地
   - 供电稳定性

## 🔬 进阶优化（如需更高频率）

### 选项1: 提高波特率

```cpp
static const uint32_t RS485_BAUD = 1500000;  // 或 2000000
```

**前提**: IMU设备和RS485收发器必须支持

### 选项2: 使用DMA传输

ESP32支持UART DMA，可实现零CPU开销传输。需要重构代码使用ESP-IDF的UART驱动。

### 选项3: IMU主动推送模式

某些IMU支持配置为主动推送数据，无需查询。查看IMU手册了解是否支持。

## 📝 重要注意事项

### 寄存器数量调整

⚠️ **极限版本将寄存器数量从22减少到11**

请确认：
- 你的IMU数据布局中，前11个寄存器是否包含所需的加速度和四元数
- 如果数据在不同位置，需要调整 `MODBUS_REG_START` 和 `MODBUS_REG_COUNT`

### 硬件要求

- **ESP32**: 任何型号（ESP32/ESP32-S3/ESP32-C3等）
- **RS485收发器**: 支持921600波特率（如MAX485、MAX3485等）
- **IMU**: 支持Modbus RTU协议，响应时间<5ms
- **总线**: 良好的屏蔽，正确的终端电阻

### 电气要求

- **总线长度**: <50米（更长距离需要降低波特率）
- **终端电阻**: 120欧姆（总线两端）
- **供电**: 稳定的5V或3.3V供电
- **屏蔽**: 使用屏蔽双绞线

## 🐛 故障排除

### 问题1: 编译错误

```
error: 'Serial2' was not declared
```

**解决**: 确保你的ESP32板子定义正确，某些开发板可能需要手动定义Serial2。

### 问题2: 无数据输出

**检查清单**:
- [ ] RS485连线正确（A-A, B-B）
- [ ] DE/RE引脚连接并控制正确
- [ ] IMU供电正常
- [ ] IMU地址配置正确（默认1和2）
- [ ] 波特率匹配

### 问题3: 数据全是0

**可能原因**:
- CRC校验失败（通信错误）
- 寄存器地址不正确
- IMU未初始化或故障

**调试方法**:
- 启用Modbus调试输出
- 使用逻辑分析仪检查通信
- 单独测试每个IMU
