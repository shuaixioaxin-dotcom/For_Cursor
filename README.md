# ESP32 多摩川编码器高速数据采集系统

## 项目概述

本项目实现了基于ESP32的多摩川编码器数据采集系统，能够以**200Hz**的频率同时读取**6个编码器**的数据，并通过**ESP-NOW**无线传输。

### 核心特性

- ✅ **高速采集**：200Hz采样率（5ms周期）
- ✅ **多路并行**：3路RS485并行通信，每路2个编码器
- ✅ **DMA加速**：使用UART DMA降低CPU占用
- ✅ **实时传输**：ESP-NOW低延迟无线传输
- ✅ **高波特率**：支持2.5Mbps RS485通信
- ✅ **双核架构**：充分利用ESP32双核性能

## 技术分析与可行性

### 时序计算

| 参数 | 数值 | 说明 |
|------|------|------|
| 目标频率 | 200Hz | 5ms采集周期 |
| 波特率 | 2.5Mbps | RS485通信速度 |
| 单帧数据 | 1发+22收=23字节 | 每个编码器 |
| 单帧耗时 | ~92μs | 23字节×10bits÷2.5Mbps |
| 单路总耗时 | ~184μs | 2个编码器顺序读取 |
| 3路并行理论耗时 | ~184μs | 受限于顺序执行 |
| 实际采集耗时 | 300-500μs | 包含切换和处理时间 |
| **可用时间余量** | **>4500μs** | 5000μs - 500μs |

**结论：完全可行，有90%以上的时间余量！**

### 为什么不能完全并行？

虽然有3路UART，但ESP32的UART驱动是顺序执行的。不过由于单次采集只需500μs，而周期是5000μs，时间余量非常充足。

### 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **3路分组（本方案）** | 时序清晰、稳定性高、编程简单 | 理论上不是最优 | **推荐，实际最优** |
| 1路顺序读取 | 接线简单 | 需要~550μs，余量较小 | 对可靠性要求不高 |
| 6路独立 | 真正并行 | ESP32只有3个UART | 不可行 |

## 硬件连接

### ESP32引脚分配

```
┌─────────────────────────────────────────────┐
│                 ESP32                        │
├─────────────────────────────────────────────┤
│ UART0 - 编码器0,1                            │
│   TX:  GPIO1    RX:  GPIO3    DE:  GPIO4    │
│                                              │
│ UART1 - 编码器2,3                            │
│   TX:  GPIO17   RX:  GPIO16   DE:  GPIO5    │
│                                              │
│ UART2 - 编码器4,5                            │
│   TX:  GPIO25   RX:  GPIO26   DE:  GPIO27   │
└─────────────────────────────────────────────┘
```

### RS485接线示意

每路RS485连接方式（以UART0为例）：

```
ESP32                RS485模块           编码器总线
GPIO1  ─────────────> TXD
GPIO3  <───────────── RXD
GPIO4  ─────────────> DE/RE
                      A+ ─────────┬───── A+（编码器0）
                                  │
                                  └───── A+（编码器1）
                      B- ─────────┬───── B-（编码器0）
                                  │
                                  └───── B-（编码器1）
GND    ─────────────> GND ────────────── GND（共地）
```

**注意事项：**
1. 每路485总线的两个编码器需要并联连接
2. 确保总线终端电阻正确配置（120Ω）
3. 所有设备必须共地
4. RS485模块需要独立供电（5V）

### 推荐RS485模块

- MAX485 / MAX3485（低成本）
- SP485 / SP3485（推荐，更稳定）
- UART转RS485模块（某宝10元左右）

## 快速开始

### 1. 环境准备

安装PlatformIO：
```bash
pip install platformio
```

或使用VSCode PlatformIO插件

### 2. 配置系统

编辑 `include/config.h`：

```cpp
// 1. 配置GPIO引脚（根据实际接线）
#define UART0_TX_PIN    1
#define UART0_RX_PIN    3
// ... 其他引脚

// 2. 配置接收端MAC地址
// 先运行接收端获取MAC地址，然后填入这里
#define RECEIVER_MAC {0xAA, 0xBB, 0xCC, 0xDD, 0xEE, 0xFF}
```

### 3. 选择版本

**使用基础版本：**
```bash
# 将 main.cpp 设为活动版本（默认）
pio run -t upload
```

**使用DMA优化版本：**
```bash
# 重命名文件
mv src/main.cpp src/main_basic.cpp
mv src/main_with_dma.cpp src/main.cpp
pio run -t upload
```

### 4. 部署接收端

在另一块ESP32上：
```bash
mv src/main.cpp src/main_backup.cpp
mv src/receiver_example.cpp src/main.cpp
pio run -t upload
pio device monitor  # 查看MAC地址
```

记录接收端MAC地址，填入发送端的`config.h`中。

### 5. 上传发送端

重新编译上传发送端程序。

### 6. 运行测试

打开接收端串口监视器（115200波特率），应该能看到数据流。

## 数据协议

### 多摩川协议

```
发送：1字节命令
  0x50 (80) - 编码器0
  0x51 (81) - 编码器1
  0x52 (82) - 编码器2
  ...
  0x55 (85) - 编码器5

接收：22字节响应
  [具体格式需要参考您的编码器文档]
```

### ESP-NOW数据包格式

```cpp
struct EncoderDataPacket {
    uint32_t timestamp;           // 时间戳（微秒）
    uint16_t sequence;            // 序列号
    uint8_t encoder_data[6][22];  // 6个编码器×22字节
    uint8_t valid_flags;          // 有效性标志（bit0-5）
    uint16_t sample_rate;         // 采样率（Hz）
    uint8_t checksum;             // 校验和
}; // 总计148字节
```

## 性能优化建议

### 已实现的优化

1. **DMA传输**：降低CPU占用
2. **双核分离**：核心1采集，核心0发送
3. **高优先级任务**：确保采集任务及时执行
4. **双缓冲**：避免数据竞争

### 可进一步优化

1. **波特率调整**：如果编码器支持，可以尝试更高波特率
2. **ESP-NOW参数**：调整WiFi信道，减少干扰
3. **硬件定时器**：使用硬件定时器替代软件延迟
4. **中断驱动**：完全基于中断的事件驱动架构

## 故障排除

### 问题1：编码器无响应

**可能原因：**
- RS485接线错误（A+/B-接反）
- 波特率不匹配
- DE/RE控制时序问题

**解决方法：**
```cpp
// 在 config.h 中启用调试
#define ENABLE_DEBUG_OUTPUT 1

// 增加切换延迟
delayMicroseconds(50);  // 在rs485SetTransmit/Receive中
```

### 问题2：数据采集频率不稳定

**可能原因：**
- WiFi干扰
- 任务优先级设置不当
- CPU占用过高

**解决方法：**
- 使用DMA版本
- 关闭不必要的调试输出
- 检查watchdog超时

### 问题3：ESP-NOW传输失败

**可能原因：**
- MAC地址配置错误
- 距离太远
- WiFi信道拥挤

**解决方法：**
```cpp
// 检查MAC地址
Serial.println(WiFi.macAddress());

// 设置固定信道
WiFi.channel(1);  // 尝试不同信道
```

### 问题4：数据校验失败

**可能原因：**
- RS485信号质量差
- 波特率过高导致误码
- 接地不良

**解决方法：**
- 降低波特率到1Mbps测试
- 缩短RS485总线长度
- 检查终端电阻
- 确保良好接地

## 常见问题

**Q: 为什么不用WiFi TCP/IP？**
A: ESP-NOW延迟更低（<1ms vs 10-50ms），更适合实时数据传输。

**Q: 可以达到500Hz吗？**
A: 理论可行，但余量很小。建议先在200Hz稳定运行后再尝试。

**Q: 支持其他编码器协议吗？**
A: 可以，只需修改`readEncoder`函数中的命令格式和响应长度。

**Q: 可以用ESP8266吗？**
A: 不推荐，ESP8266只有1个完整UART，且性能不足。
