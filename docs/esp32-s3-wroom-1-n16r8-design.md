# ESP32-S3-WROOM-1（N16R8）方案设计笔记

面向需求：
- USB Serial JTAG/Type‑C 或 UART 下载口
- 按键 2 + 电源导通开关 1（仅硬件）
- LED 3 + ADC 电压采样（RC 滤波）
- SPI 编码器 21 路（SPI 4 线，Mode0，CRC，最高 10Mb/s，≥60Hz 采样）
- 无线：Wi‑Fi 2.4GHz UDP 为主链路，BLE 做配网/控制；支持 2 台 ESP32 同时向同一台 PC 发数据

---

## 1. 推荐总体架构（硬件）

### 1.1 供电
- **输入**：3.5V（来自外部电源/电池管理模块等）
- **3.3V 主电源**：给 ESP32‑S3 模组、SPI 编码器、74HC595、LED 等
- **稳压建议**
  - 若对 RF/ADC 噪声敏感：优先 **Buck(3.5→3.3) + LDO(3.3→3.3 RF/模拟隔离)** 或直接选低噪声 Buck；
  - 若电流裕量足且压差很小：可用 **低压差 LDO**（需满足 Wi‑Fi 峰值电流与散热）。
- **电流与去耦**：ESP32‑S3 Wi‑Fi 峰值电流可到数百 mA，3.3V 轨上放置：
  - 模组电源脚旁：0.1µF×2 + 1µF + 10µF（尽量贴近）
  - 3.3V 总线上：22µF~100µF（根据瞬态压降评估）
- **地/电源分区**：RF 区、开关电源区、SPI 大电流翻转区尽量分开；单点/大地平面回流，避免让开关电源回流穿过天线附近。

### 1.2 USB Type‑C（优先推荐：直接用 ESP32‑S3 USB Serial/JTAG）
ESP32‑S3 原生支持 USB Serial/JTAG，推荐用于烧录与日志输出，减少外置 USB‑UART 芯片。

- **Type‑C 作为 UFP（设备端）**：
  - CC1/CC2 各放 **5.1kΩ 下拉到 GND**（Rd）
  - VBUS（5V）建议：自恢复保险丝/限流 + TVS；并可用作“插线检测”（可选）
- **数据线**：
  - D+ / D− 走差分，90Ω，短且等长；靠近 MCU 端各串 **22Ω（常用 22~33Ω）** 抑制振铃
  - 连接器侧加 **USB ESD 二极管阵列**（低电容）
- **S3 USB 引脚**（常用映射）：GPIO20=USB_D+，GPIO19=USB_D−（以芯片/模组手册为准）

> 仍建议保留 UART0（U0TXD/U0RXD）焊盘用于工装/故障恢复。

### 1.3 UART 下载口（备选）
若你希望“无驱动/兼容性更强/不占用 S3 USB 引脚”，可加 CP2102N/CH343 等 USB‑UART。
- 预留：UART0 TX/RX、EN、IO0（自动下载电路可选）
- 同时保留原生 USB 也是可行的（但注意空间与布线复杂度）。

## 2. SPI 21 路编码器设计

### 2.1 总线与速率
需求：SPI 4 线、Mode0、带 CRC，最高 10Mb/s；每个编码器角度值采样频率 ≥60Hz（16ms 周期）。

**带宽估算（举例）**：
若每路一次读取 \(N\) 字节（含 CRC/命令开销），总比特约 \(21 \times 8N\)。
即便 N=8B，总比特约 1344bit，10Mb/s 下仅 0.134ms（不含片选切换/软件开销）。  
因此瓶颈通常在：CS 切换效率、事务管理、布线质量、编码器响应延迟。

### 2.2 片选实现：强烈推荐 74HC595（减少 IO 且避免毛刺）
你已提出方案：**3×74HC595（24 路）+ RCLK 锁存 + OE 控制**，这是较优解：
- **SER**：串行数据输入
- **SRCLK**：移位时钟
- **RCLK**：锁存时钟（一次性更新 24 路输出，避免移位过程毛刺影响 CS）
- **OE**：输出使能（建议默认关闭输出，更新完再打开；或用于全局关闭 CS）

推荐连线：
- 24 路输出中取 21 路给 CS1..CS21，剩余 3 路可预留（扩展/调试）
- 每路 CS 走线近端串 22~100Ω（视走线长度与边沿而定）以减反射（可选）

> 关键点：更新 CS 时先 OE=1（高阻/关闭），移位 24bit → RCLK 上升沿锁存 → OE=0 开启输出；这样能最大程度消除“移位瞬间”的毛刺误选通。

### 2.3 SPI 布线与信号完整性建议
- SCLK/MOSI 边沿最敏感：尽量短，必要时在主控端串联 22~47Ω
- MISO 走线避免与天线区/开关电源高 dv/dt 区并行
- 编码器供电去耦：每颗编码器就近 0.1µF
- 若 21 路分布较远：建议分区布线、加地参考、必要时降低 SCLK 边沿或速率以换可靠性

## 3. 按键/LED/ADC 硬件要点

### 3.1 按键（A/B）与电源开关
- 按键 A/B：GPIO 上拉（内部或外部），按下接地；加 RC 去抖（如 10k + 100nF）或软件去抖
- 电源导通开关：按你描述“硬件软件无需考虑”，可作为电源路径开关（自锁/轻触保持电路）或直接串电源

### 3.2 LED（3 路）
建议：GPIO → 限流电阻（330Ω~1k）→ LED → GND（或反向灌电流方式），统一为“高亮=1/0”便于软件。
- LED0：电源状态灯（由 ADC 阈值控制闪烁）
- LED1：数据传输状态灯
- LED2：自检/异常状态灯

### 3.3 ADC 电压检测（带 RC 滤波）
需求阈值：>=3.4V、3.3~3.4V、<3.3V；电源输入 3.5V。

建议采样目标：
- 若想判定“系统 3.3V 轨是否掉压”：测 **3.3V** 更直接；
- 若想判定“输入 3.5V 是否异常”：测 **输入 3.5V**，需分压到 ADC 量程内。

典型电路：
- 分压：R1（上）+ R2（下）到 ADC，选择使满量程 < ADC 允许电压（通常 3.3V 内）
  - 例：测 3.5V → 2.8V：R1=100k，R2=390k（仅示例，实际按精度/输入阻抗/功耗调整）
- RC：ADC 脚前串 1k~4.7k，ADC 脚对地 100nF~1µF（形成低通滤波）
- 若分压阻值很大：注意 ADC 采样保持电容导致误差，必要时降低阻值或加缓冲

## 4. RF（Wi‑Fi/BLE）抗干扰与布局布线“硬规则”

ESP32‑S3 的 Wi‑Fi/BLE 表现高度依赖 PCB 细节，建议至少做到：
- **天线 keep‑out**：模组天线区域下方与周围按手册要求禁布铜/禁走线/禁放器件
- **开关电源远离天线**：Buck 电感、SW 节点、二极管（或同步管）远离天线区，走线短且回路面积小
- **USB/SPI 高速线远离天线**：SCLK、USB D+/D− 不与天线并行靠近
- **整板地平面完整**：不要在天线馈电附近切割地；关键回流路径连续
- **去耦就近**：模组 3.3V 去耦电容必须贴近电源脚；74HC595 与编码器同理
- **必要时加屏蔽/隔离**：若编码器线束很长或外部干扰大，可考虑分区、地参考、共模电感/TVS（看接口形态）

## 5. 引脚规划（建议稿）

由于你未给出“必须使用的管脚/板形限制”，下面给一份“可落地且避开常见风险”的建议分配，实际还应对照：
- ESP32‑S3 strapping/保留管脚（IO0 等）
- 模组手册关于 USB/PSRAM/Flash 占用

### 5.1 必须预留
- **EN**：复位
- **IO0**：下载模式（建议做按键或焊盘）
- **UART0 TX/RX**：作为备份日志/下载口焊盘

### 5.2 推荐分配（示例）
- **USB**：GPIO19(D−)、GPIO20(D+)
- **SPI 编码器主总线**：SCLK / MOSI / MISO 各 1（选一组稳定 GPIO，避开 strapping）
- **74HC595 控制**：SER、SRCLK、RCLK、OE 共 4（替代 21 路 CS 直出）
- **LED**：3 路 GPIO
- **KEY**：2 路 GPIO
- **ADC**：1 路 ADC1 GPIO
- **UART0**：U0TXD/U0RXD 焊盘预留

> 采用 74HC595 后，总 IO 压力显著下降，也更利于 RF 布局（少走 21 根 CS 长线）。

## 6. 应用层功能（按你的逻辑，建议的软件实现要点）

### 6.1 上电初始化
1) 读取 ADC → 驱动 LED0：
- 阈值Ⅰ：>=3.4V → LED0 常亮
- 阈值Ⅱ：3.3~3.4V → LED0 0.5s 闪烁
- 阈值Ⅲ：<3.3V → LED0 3s 闪烁

2) 默认数据停止发送：LED1 常亮  
3) 自检灯：LED2 常灭

### 6.2 按键 A
短按：发送单次 21 路编码器值（LED1 常亮 1s）  
长按：进入自检（LED1 常灭），检测 21 路值是否都有变化：
- CS1‑CS7 异常：LED2 一长一短
- CS8‑CS14 异常：LED2 两长一短
- CS15‑CS21 异常：LED2 两短一长
- 无异常：LED2 常亮 3s
节拍：长 1s，短 0.2s；多路异常时，提示之间间隔 3s。

实现建议：
- 每路采样一段时间窗口（例如 0.5~1s 内采多次），若角度变化幅度/CRC 错误率异常则判故障
- 统计 CRC 错误/超时次数，作为“总线质量”指标输出到 PC 便于排查

### 6.3 按键 B
短按：开始无线采集并持续 UDP 发送（LED1 0.1s 闪烁）  
再次短按：停止无线采集（不断开 Wi‑Fi/BLE 连接，仅暂停发送）（LED1 常亮）

## 7. Wi‑Fi UDP“尽可能少丢包”的工程建议

UDP 天生不保证到达，想“尽可能少丢包”，建议在应用层加“轻量可靠性”：
- **包结构**：包含设备 ID、递增序号、时间戳、payload 长度、CRC
- **丢包检测**：PC 端按序号检测丢包率
- **可选重传**：PC 端周期性回 ACK（最后收到序号），ESP32 按窗口重传少量丢失包（折中实时性）
- **发送策略**：按固定周期发送（60Hz），避免突发大包；必要时把 21 路打包成一个帧

ESP‑IDF 侧关键配置（方向性建议）：
- 关闭省电：`WIFI_PS_NONE`
- 固定信道/固定带宽（若可控 AP）：减少漫游与信道切换
- 合理设置 socket 缓冲（`SO_SNDBUF`/`SO_RCVBUF`）
- BLE 仅用于配网/控制，正常采集时尽量减少 BLE 广播/连接事件占空（改善共存）

## 8. 除 Wi‑Fi/BLE 外，还能用什么无线方式把数据发到 PC？

在“PC 直连/近距离/低丢包/实时性”场景下可选：

1) **ESP‑NOW（推荐作为 Wi‑Fi UDP 的备选链路/冗余链路）**
- 优点：延迟低、无需 AP、实现简单、抗拥塞能力在某些环境更好
- 缺点：PC 原生不支持，需要 **USB‑Wi‑Fi 网卡/ESP32 网关**（PC←USB 串口/网口←网关←ESP‑NOW）

2) **Wi‑Fi TCP（或 QUIC/自定义可靠 UDP）**
- 优点：可靠性强（TCP），PC 端实现简单
- 缺点：拥塞控制可能引入抖动/延迟尖峰；对“强实时”不如 UDP+轻量重传可控

3) **外置 2.4GHz 专用收发（nRF24L01 等）**
- 优点：链路可控、低延迟
- 缺点：PC 仍需 USB dongle/网关，系统集成成本上升

4) **LoRa/Sub‑GHz（若距离远、带宽低可接受）**
- 优点：远距离、穿透好
- 缺点：带宽很低，不适合高频 21 路角度流

5) **UWB（若需要高精度定位/抗多径）**
- 优点：抗多径、低延迟
- 缺点：成本与复杂度高，PC 端仍需适配器

> 若你的核心目标是“实时 + 少丢包 + PC 端易用”，综合成本通常是：**Wi‑Fi UDP + 序号/CRC + 可选 ACK 重传** 最划算；若环境干扰大再加 **ESP‑NOW 冗余/备份链路** 或做网关聚合。
