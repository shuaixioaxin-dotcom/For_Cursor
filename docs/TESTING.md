# 测试指南

## 测试流程

### 第一阶段：单元测试

#### 测试1：RS485通信基础测试

**目标：** 验证单个UART能否正常与编码器通信

**步骤：**
1. 只连接编码器0到UART0
2. 使用基础版本代码
3. 启用调试输出
4. 检查串口输出

**预期结果：**
```
编码器 0x50 读取成功，数据：AA BB CC DD ...
```

**常见问题：**
- "超时"：检查接线、波特率、编码器地址
- 无输出：检查DE/RE引脚控制
- 数据乱码：波特率不匹配

#### 测试2：多编码器顺序读取

**目标：** 验证同一总线上读取多个编码器

**步骤：**
1. 连接编码器0和1到UART0
2. 观察两个编码器是否都能正常读取
3. 检查采集时间

**预期结果：**
```
编码器0: 成功
编码器1: 成功
单次采集耗时: <200us
```

#### 测试3：并行读取测试

**目标：** 验证3路UART同时工作

**步骤：**
1. 连接所有6个编码器
2. 运行完整程序
3. 检查valid_flags是否为0x3F（所有位为1）

**预期结果：**
```
读取成功: enc[111111], 用时: 400-600 us
数据有效标志: 0x3F
```

### 第二阶段：性能测试

#### 测试4：采样频率验证

**目标：** 确认实际采样率达到200Hz

**方法A：通过序列号计算**
```
记录10秒内的序列号增量
实际频率 = 序列号增量 / 10
应该约等于 200Hz
```

**方法B：通过时间戳计算**
```
记录连续两个数据包的timestamp差值
理论值应该是 5000us (200Hz)
```

#### 测试5：持续稳定性测试

**目标：** 长时间运行无掉包

**步骤：**
1. 连续运行30分钟
2. 记录成功/失败次数
3. 计算丢包率

**预期结果：**
```
总采样次数: 360000 (200Hz × 1800s)
成功次数: >357000
成功率: >99%
```

#### 测试6：极限频率测试

**目标：** 找到系统最高稳定频率

**步骤：**
1. 逐步提高TARGET_FREQ_HZ：200 → 300 → 400 → 500
2. 每个频率测试5分钟
3. 观察成功率和CPU占用

**记录表格：**
| 频率 | 成功率 | CPU占用 | 最大延迟 | 结论 |
|------|--------|---------|----------|------|
| 200Hz | 99.9% | 10% | 500us | ✓ 推荐 |
| 300Hz | 99.5% | 15% | 550us | ✓ 可用 |
| 400Hz | 98% | 20% | 600us | △ 勉强 |
| 500Hz | 95% | 30% | 800us | ✗ 不稳定 |

### 第三阶段：可靠性测试

#### 测试7：环境干扰测试

**干扰源：**
- WiFi路由器（2.4GHz）
- 蓝牙设备
- 微波炉
- 其他ESP32设备

**步骤：**
1. 正常运行系统
2. 逐个引入干扰源
3. 观察数据包丢失情况

**改进措施：**
```cpp
// 固定WiFi信道，避开拥挤频段
WiFi.channel(1);   // 或 6, 11
```

#### 测试8：距离测试

**目标：** 确定ESP-NOW可靠通信距离

**步骤：**
1. 从1米开始测试
2. 逐步增加到10米、20米、50米
3. 记录不同距离的丢包率

**典型结果：**
- <10米：几乎无丢包
- 10-30米：偶尔丢包（<1%）
- 30-50米：丢包增加（1-5%）
- >50米：不可靠（>10%）

**改善方案：**
- 使用外置天线
- 减少障碍物
- 增加中继节点

#### 测试9：温度测试

**目标：** 验证不同温度下的稳定性

**场景：**
- 室温（20-25°C）：基准测试
- 低温（0-10°C）：冬季环境
- 高温（40-50°C）：密闭机箱

**监控项：**
- CPU温度
- 丢包率变化
- 响应时间变化

### 第四阶段：压力测试

#### 测试10：连续运行测试

**目标：** 验证24小时无故障运行

**监控指标：**
```
运行时长: 24小时
总采样次数: 17,280,000
成功次数: _______
失败次数: _______
成功率: ______%
最大CPU温度: ____°C
平均CPU占用: ____%
```

#### 测试11：断电恢复测试

**步骤：**
1. 正常运行中突然断电
2. 重新上电
3. 观察系统是否能自动恢复

**预期：**
- ESP32自动重启
- 重新初始化所有外设
- 自动重连ESP-NOW
- 继续正常采集

#### 测试12：编码器故障测试

**场景：**
- 单个编码器断电
- 单个编码器响应超时
- RS485线路短路/断开

**系统应对：**
```
编码器0故障 -> valid_flags = 0x3E (bit0=0)
其余编码器继续正常工作
系统不崩溃，继续运行
```

### 工具2：Python测试脚本

创建 `test_receiver.py`：

```python
import serial
import time

ser = serial.Serial('/dev/ttyUSB0', 115200)
packet_count = 0
error_count = 0
last_seq = -1

while True:
    line = ser.readline().decode('utf-8', errors='ignore')
    if '序列号' in line:
        # 解析序列号
        seq = int(line.split(':')[1].strip())
        if last_seq >= 0 and seq != last_seq + 1:
            error_count += 1
            print(f"序列号跳变: {last_seq} -> {seq}")
        last_seq = seq
        packet_count += 1
        
        if packet_count % 100 == 0:
            print(f"已接收 {packet_count} 包，丢包 {error_count} 次")
```

### 工具3：逻辑分析仪

**推荐设备：**
- Saleae Logic Analyzer
- 便宜替代：8通道USB逻辑分析仪（￥50）

**抓取信号：**
- CH0: UART0 TX
- CH1: UART0 RX
- CH2: UART0 DE
- CH3: UART1 TX
- ... 依此类推

**分析重点：**
- 发送和接收的时序
- DE/RE切换时机
- 数据帧格式

### 工具4：示波器

**测量项目：**
- RS485差分信号质量（A+-B-）
- 信号上升/下降时间
- 过冲和振铃
- 终端电阻匹配效果

**优质信号特征：**
- 方波清晰
- 无明显过冲
- 上升时间<100ns

## 自动化测试脚本

创建 `scripts/auto_test.sh`：

```bash
#!/bin/bash
echo "ESP32编码器系统自动化测试"
echo "================================"

# 编译并上传
echo "[1/4] 编译固件..."
pio run

echo "[2/4] 上传固件..."
pio run -t upload

echo "[3/4] 等待系统启动..."
sleep 5

echo "[4/4] 开始监控（按Ctrl+C停止）..."
pio device monitor | tee test_log_$(date +%Y%m%d_%H%M%S).txt
```

运行测试：
```bash
chmod +x scripts/auto_test.sh
./scripts/auto_test.sh
```
