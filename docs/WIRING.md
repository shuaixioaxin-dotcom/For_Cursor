### ESP32 接收端

接收端无需特殊接线，只需：
- USB供电或外部5V供电
- 连接USB串口到PC（用于查看数据）

## RS485总线拓扑

每路RS485总线（以UART0为例）：

```
RS485模块
  A+ ─────┬───────┬─────── 120Ω ───┐
          │       │                │
      编码器0   编码器1         (终端电阻)
          │       │                │
  B- ─────┴───────┴────────────────┘
```

**重要提示：**
1. 总线两端需要120Ω终端电阻
2. 编码器采用菊花链（并联）连接
3. 总线长度建议<10米（2.5Mbps）
4. 使用双绞线，屏蔽层接地

## 供电建议

### 方案A：USB供电（开发测试）
```
USB 5V ──> ESP32
         └─> 3个RS485模块（通过ESP32 5V引脚）
```
**限制：** 电流不足，仅适合测试

### 方案B：外部供电（生产环境）★推荐
```
5V/2A电源 ──┬──> ESP32 (VIN引脚)
            ├──> RS485模块1
            ├──> RS485模块2
            ├──> RS485模块3
            └──> 编码器（如果需要）
```

### 方案C：独立供电（最稳定）
```
5V/1A ──> ESP32
5V/1A ──> 3个RS485模块
24V/1A ──> 编码器（根据编码器规格）
```
**注意：** 所有设备必须共地！

## 常见接线错误

### ❌ 错误1：A+/B-接反
**症状：** 完全无法通信  
**检查：** 用万用表测量差分电压

### ❌ 错误2：忘记接DE/RE
**症状：** 只能发送或接收  
**检查：** DE/RE引脚必须连接到ESP32 GPIO

### ❌ 错误3：未共地
**症状：** 通信不稳定，误码率高  
**检查：** 所有GND必须连接在一起

### ❌ 错误4：总线过长
**症状：** 偶尔通信失败  
**解决：** 降低波特率或缩短线缆

### ❌ 错误5：没有终端电阻
**症状：** 高波特率下反射干扰  
**解决：** 在总线两端加120Ω电阻

## 调试技巧

### 1. 逐步测试

```
步骤1: 只连接1个编码器到UART0
步骤2: 成功后添加第2个编码器到UART0
步骤3: 依次添加UART1和UART2的编码器
```

### 2. 波特率递减测试

如果2.5Mbps不稳定：
```cpp
// 在 config.h 中修改
#define UART_BAUD_RATE  1000000  // 先用1Mbps测试
#define UART_BAUD_RATE  2500000  // 稳定后提升到2.5Mbps
```

### 3. 使用示波器

检查信号：
- A+和B-之间差分电压应该有明显波形
- 波特率正确时应该看到规律的脉冲
- 如果波形失真严重，检查终端电阻

### 4. 使用逻辑分析仪

抓取UART信号：
- 连接到ESP32的TX/RX引脚
- 设置波特率为2.5Mbps
- 检查发送的命令字节是否正确

## 推荐硬件

### RS485模块
- **MAX485模块**：￥3-5元，基础款
- **MAX3485模块**：￥5-8元，带保护
- **SP485模块**：￥8-12元，推荐，更稳定

### 线缆
- **屏蔽双绞线**：CAT5/CAT6网线（推荐）
- **RS485专用线**：更好的抗干扰性
- 避免使用普通杜邦线！

### 终端电阻
- **120Ω 1/4W**：标准配置
- 或使用**并联240Ω电阻**（两个并联）

### 供电
- **5V/2A开关电源**：基础配置
- **5V/3A电源**：推荐，余量充足
